## 로컬에서 반복하는 순서

1. Node 22 이상을 사용한다. 이번 셸 기본 Node 18은 JSON import attributes를 파싱하지 못했으며, 이를 제품 버그로 판단하지 않았다.
2. `front`에서 `npm test`, `npm run lint`, `npm run build`를 실행한다. 새 테스트는 기존 실행 패턴에 포함된다.
3. `back`에서 `./gradlew test`를 실행한다. **현재 테스트는 H2가 아니라 로컬 MySQL을 사용한다.** 차량 회귀 테스트의 임시 행은 트랜잭션으로 롤백한다. Spring 테스트 시작 시 Flyway가 실행될 수 있다. 테스트 로그에서 스키마 버전 44를 확인했다.
4. 프로젝트 루트에서 `PYTHONPATH=ml:ml/tests ml/.venv/bin/python -m unittest test_runtime_catalog_api test_managed_snapshot test_managed_costs`를 실행한다.
5. 백엔드·ML 변경은 기존 실행 절차로 재시작한 뒤 확인한다. 이번 작업에서 실행 중 Spring·ML 프로세스를 재시작하거나 모델을 교체하지 않았다. 프런트는 실행 중 Vite의 변경 반영으로 확인했다.
6. 브라우저 개발자 도구 Network에서 Preserve log를 켜고 요청 URL·상태·본문을 확인한다. 실패 검증은 개발자 도구 Request blocking으로 **대상 GET 또는 저장 요청만** 차단한다. 모델 제어 POST는 성공시키고 후속 GET만 차단해야 7번 조건을 검증할 수 있다.
7. 경고·권한·삭제·탈퇴는 실제 사용 계정 대신 로컬 테스트 계정과 식별 가능한 임시 데이터를 사용한다. Network의 응답뿐 아니라 다시 조회한 실제 상태도 확인한다. 토큰·비밀번호는 검증 기록에 복사하지 않는다.

## 추천 카탈로그 변경 후 복구

1. 원본은 공개 차량 API `/api/v1/vehicles/recommendation-catalog`다. 변경 전후 ID·가격·제원과 현재 모델 metadata의 training catalog 출처를 비교한다.
2. 추천이 503이면 기존 모델의 catalog.json이나 해시만 수작업 수정하지 않는다. 변경된 원본으로 학습 데이터·제원/취향 매핑을 갱신하고 `train_ui_scenario`의 audit를 통과시킨 뒤 **새 출력 폴더**에 학습한다. 데이터 갱신은 현재 학습 묶음의 생성 절차와 `ml/README.md`를 따른다. 학습 입력이 맞지 않으면 먼저 그 원인을 해결한다.
3. `ml`에서 `python -m vehicle_matching.train_ui_scenario --data <검증한 새 학습 데이터 폴더> --output <새 모델 출력 폴더> --epochs 30`을 사용한다. 경로는 현재 묶음을 확인해 지정해야 하며 기존 학습 결과를 덮어쓰지 않는다.
4. 기존 실행 방식의 RUN을 새 출력 폴더로 지정해 모델을 교체한다. `ml/serve-candidates.sh`가 현재 macOS 실행 진입점이다. 서버 재시작은 사용 중인 실행 창에서 수행한다.
5. 관리자 후보 API·실행 ML 후보 API·공개 차량 API의 ID 집합과 주요 제원을 대조하고 같은 추천 입력이 200으로 복구되는지 확인한다. 단순 건수 일치만으로 통과 처리하지 않는다.

## 변경 계약과 제한

- V44는 `input_snapshots.diagnosis_request_id`와 회원별 UNIQUE 인덱스를 추가한다. 기존 행은 NULL이며 기존 기록을 삭제하지 않는다. 기존 요청의 requestId 생략도 허용한다.
- 진단 POST는 requestId를 보내는 호출에서 같은 회원·요청 번호의 저장 결과를 반환한다. 재시도는 같은 번호를 사용해야 한다.
- 관리자 회원 목록에 `sort`, `direction`, 상담 목록에 `offset`, 상담 상세에 `/rooms/{id}`가 추가됐다. 기존 파라미터 기본값은 유지한다.
- 신규 공용 모듈: `purchaseScenario`는 추천 구매조건 변환, `dreamCarStorage`는 회원별 저장 키와 정리를 담당한다. 화면 렌더링과 HTTP 처리는 각 기능에 남긴다.
- 기존 소유자 불명 브라우저 데이터는 보존하지만 자동 표시·알림에는 사용하지 않는다. 사용자가 소유자를 확인하지 않은 상태로 이관하지 않는다.
- 실제 공개 차량 변경·모델 재학습·계정 전환·권한 변경·탈퇴·관리자 강제 장애 주입을 이번 화면 검증에서 실행하지 않았다. 조건부 항목의 운영 환경 완료로 해석하지 않는다.
